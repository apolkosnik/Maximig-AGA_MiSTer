# The AA3000+ (branch `AA3000`)

Commodore's A3000+/AA3000 prototype, as the machine was built in 1991-92 by
Dave Haynie's group, plus this core's extras: the A3000 motherboard (Fat
Gary, Ramsey, the SuperDMAC with the WD33C93 SCSI controller, Fat Buster
and Zorro III), the AGA chipset (Alice, Lisa) on the A3000 32-bit chip bus,
and the AT&T DSP3210 at 50 MHz as a second bus master with its host
interface.

## References, in order of authority

1. The DSP3210 support logic's PLD sources (U122 bus interface, U123
   arbiter, U124 DMAC kludge, U701 clock/interrupts): Dave Haynie's 1992
   originals with Thomas Winischhofer's and Wrangler's 2020-21 fixes,
   github.com/realA10001986/Amiga `GALs/` and github.com/Wrangler491/AA3000-DSP.
   Real boards run with these.
2. *WE DSP3210 Digital Signal Processor Information Manual*, AT&T,
   September 1991 (the scanned and OCR'd copy in realA10001986/Amiga
   `Doc/`, and Wrangler491/AA3000-DSP).
3. *The Amiga 3000+ System Specification* rev 0.6, Dave Haynie, July 1991
   (the Haynie archive, `research/a3000p/docs/a3000p.pdf`), and Haynie's
   *Cheap-Ass Low-Level DSP Programming Notes* (`dspprg.pdf`).  Where the
   1991 paper design and the AA3000 boards differ, the boards win: the
   DSP control register is the U124 latch at `$DD0080` (write, byte) read
   back through the DMAC+ at `$DD005C` (long word), not the spec's
   coprocessor register at `$DD0050`; Gary+ (`$DE1000` DSPRST, GARYID
   `$90`) was never built, the boards carry Fat Gary.
4. The DSP32C data sheet (DS94-084, AT&T 1996): instruction encodings the
   DSP3210 shares.
5. WinUAE: `dsp3210/` (Mark Wrangler's DSP3210 emulator, its on-chip boot
   ROM image, the host glue), `a2091.cpp` (the A3000 SuperDMAC and the
   WD33C93), `gayle.cpp`.
6. Software that must run: Thomas Winischhofer's dsp3210.resource/
   .device/.library and dsp3210devtest (Aminet driver/other/dsp3210),
   Wrangler's *What Might Have Been* (Aminet demo/aga/WhatMightHaveBeen),
   Kickstart 3.1 for the A3000 (40.62/40.68: the SuperDMAC scsi.device).

## The CPU

Chosen by the machine's `CPU_CARD` parameter at build time; only that card
is built.  The BFG9060 (68040, from the a4000-core branch) for now; the
AA3000's own 25 MHz 68030 (AP68030) on the motherboard is the next choice.

## Memory map (differences from the A4000 core)

| address | target |
|---|---|
| `$00DD0000-$00DD1FFF` | the DMAC+: SuperDMAC registers, the WD33C93 (`$DD0041`/`$DD0047`/`$DD0049`), the DSP status (`$DD005C`, read), the DSP control latch (U124: writes with A7 set, `$DD0080`); mirrored every `$100` |
| `$00DD2000-$00DD3FFF` | nothing: no A4000 IDE port (the disks are SCSI) |
| `$01000000-$011FFFFF` | chip RAM again (the A3000+'s 32-bit chip RAM window) |
| `$03E00000-$03E7FFFF`, `$03F80000-$03FFFFFF` | the ROM again (the 4 MB ROM space's top) |

## Bus masters

The local bus gets an arbiter (U123's role, Buster's fast arbiter): the CPU
card, the SuperDMAC's SCSI DMA and the DSP3210.  The DSP has the highest
priority and keeps the bus while it asks for it (U123: dspCYC holds while
dspBR, dspBGACK or a snooped cycle continues), so a DSP running from host
memory stalls the CPU, as on the real machine.  The DSP's cycles are
68030 cycles of 32 bits only (U122: SIZ from the DSP's MS3/MS2, Supervisor
Data function code); an access to an 8- or 16-bit port gets a bus error.
No bursts (U122/U123 never answer CBREQ: `doblock` must not be used).

## Phases

1. The motherboard: CPU_CARD, the A3000 decode, the DMAC+ register file
   with the DSP control/status (no DSP yet: its interrupt lines idle), the
   local-bus master arbiter.
2. SCSI: the WD33C93 (SBIC) with the SuperDMAC's FIFO and DMA, SCSI disk
   targets backed by the MiSTer's hard disk images.
3. The DSP3210 core: CAU, DAU (DSP32 floating point, the visible
   four-stage pipeline and its latencies), on-chip RAM and boot ROM, the
   I/O registers, exceptions and interrupts, the timer, BIO, serial I/O
   and its DMA; checked instruction by instruction against WinUAE's
   emulator.
4. The DSP on the bus (U122/U123/U701 timing) and the host interrupts
   (BIO6/BIO7 to INT6/INT2 through the U124 masks); the hi-fi CODEC on
   the serial bus to the MiSTer's audio.

## Status

Phases 1-3 are in, and phase 4's bus side: the DSP3210 core (a3kp_dsp3210,
tb/dsp3210: an assembler for the manual's syntax and the core's tests) on
the arbiter's DSP port, U124's reset and INT0/INT1, BIO6/BIO7 to INT6/INT2,
CKI at 7/8 of clk_57 (~50 MHz), its beats to 8- and 16-bit ports a bus
error (a4k_lbus, lb_dsp).  t_dsp boots it as dsp3210.resource does.  Still
to come: the SIO and its DMA, the hi-fi CODEC.

The core does not fit yet: alone it is about 7,100 ALMs (Quartus 17,
5CSEBA6), the AA3000+ build leaves about 2,500 free.  Its CA execution
(three register reads, the ALU, the register file's write sources) is about
3,800 of them, the conversions about 1,300.  Maximig.sv builds a4k_machine
with DSP3210 0 until it does; the benches build it with the DSP.

Kickstart 3.1's scsi.device (A3000) drives the WD33C93 with long words and
Level II commands (Select-With-ATN, Transfer Info): t_scsi checks both.
It needs a rigid disk block on the disk: a bare partition image ("DOS" at
block 0) is found only when Main presents it with a made-up RDB.
